# Last updated: 2026-06-22 (pi-style LLM summarization compaction)

- **Pi-style LLM summarization compaction (2026-06-22)** — Replaced Dirac-style
  half/quarter truncation with pi's LLM summarization approach.  New module
  `core/pi_compaction.py` (470 lines) implements:
  - **Structured summaries**: Goal, Constraints, Progress (Done/In Progress/
    Blocked), Key Decisions, Next Steps, Critical Context + file tracking.
  - **Pi-style thresholds**: `contextTokens > contextWindow - reserveTokens`
    (default reserve=16384, fires at ~984K on 1M window).  pi lets context
    grow as much as possible, compacting only near the limit.
  - **Iterative updates**: if a previous compaction summary exists, the
    UPDATE_SUMMARIZATION_PROMPT merges new info instead of regenerating.
  - **File tracking**: read_files and modified_files extracted from tool
    calls, appended as `<read-files>` / `<modified-files>` tags.
  - **Keep recent**: configurable keep_recent_tokens (default 20K pi default),
    keeping the most recent conversation verbatim.
  - `_compact_if_needed()` in `context_inject.py` now delegates to
    `pi_compaction.compact()` instead of Dirac truncation.
  - `COMPACTION_HARD_LIMIT` raised from 200K to 1M to match deepseek-v4-pro's
    actual context window.  pi-style compaction uses the model's reported
    context_window from config, not the hard cap.
  - Previous compaction summary stored on `_TOOL_CONTEXT._pi_compaction_summary`
    for iterative updates across compactions.

- **Git skill (2026-06-22)** — Created `skills/git/` skill with 5 Windows-safe
  tools: git_status, git_diff, git_log, git_add, git_commit.  All use
  subprocess.run() with GIT_TERMINAL_PROMPT=0, capture_output, text=True,
  and a 15-second timeout to prevent hangs on Windows 11 (credential prompts,
  AV scanning, pipe buffer deadlocks).  Implemented in `tools/git_ops.py`.
  Added to `.mini_agent.rules` with guidance to use git tools instead of
  `run_shell` for git operations.  Previously the LLM called `use_skill('git')`
  which failed (skill didn't exist), then fell back to `run_shell` with raw
  git commands that hung on Windows (120s timeout).

- **write_session_handoff freeze fix (2026-06-22)** — The `.mini_agent.rules`
  instruction "Before signing off: write_session_handoff(pending='...')" caused
  the LLM to call a non-existent tool every turn. Since the tool had no schema
  or dispatch, the LLM either got "Unknown tool" errors (retry loop) or fell
  back to `run_shell` with Python code that called `MemoryStore.write_session_handoff()`
  which ran git subprocesses that HANG on Windows (credential prompts, antivirus,
  large repos).
  
  Fixes:
  1. **Registered `write_session_handoff` as a proper tool** (schema + dispatch
     in tools/agent_ops.py + tools/schema.py), added to CORE_TOOLS in skills.py.
     The tool writes a lightweight HANDOFF.md WITHOUT running git (no subprocess
     hangs). The full git-diff handoff is always auto-generated at session end.
  2. **Fixed `.mini_agent.rules`** — tells the agent that HANDOFF.md is
     auto-generated and the tool is only for mid-session checkpoints.
  3. **Made `MemoryStore.write_session_handoff()` Windows-safe** — catches
     `FileNotFoundError` (git not installed) and broader exceptions beyond
     just `OSError`/`TimeoutExpired` for pipe deadlocks.
  4. **Made `bootstrap.py` git rev-parse Windows-safe** — added
     `FileNotFoundError` to the exception handler.

- **Pi-style static prompt minimization (2026-06-22)** — Static system prompt
  slashed from ~2000 tokens to ~275 tokens (7x reduction). All detailed
  behavioral instructions moved to .mini_agent.rules (appended at end, outside
  cache prefix). This frees ~1700 tokens of DeepSeek KV-cache budget for
  conversation history, dramatically improving cache hit rates.  The prompt
  follows pi's ultra-minimal pattern: identity, tools list, guidelines (~7
  items), and project doc references.  All detailed rules (loop prevention,
  edit policies, Windows commands, ACI guardrails, AST tools, multi-agent,
  token efficiency) now live in .mini_agent.rules as a "AI Behavioral Rules"
  section.

- **Extended cache_control coverage (2026-06-22)** — cache_control markers
  now extend beyond the system message to cover session header, memory
  snapshot, and startup context (via _cache_mark field).  Messages marked
  _cache_mark get ephemeral cache_control in api.py.  This anchors the
  entire immutable prefix (system + session header + memory + startup) in
  DeepSeek's KV cache, not just the system prompt.

- **Per-turn injection pruning (2026-06-22)** — Disabled 12 of 18 per-turn
  context injections to reduce cache churn.  Only essential injections remain:
  compaction, circuit breaker, interjections, progress check, modified-files
  checkpoint, stale tool compression, and system reminder.  Disabled:
  cache degradation alert, edit risk, pattern rules, scratchpad nudge,
  strategy hint, plan status, self-critique, confidence nudge, tool graph,
  experience context, dead tool pruning, post-edit verification, auto
  skeletons, mistake count, condensation warning.  Injection intervals
  also relaxed: progress check every 10 turns (was 5), scratchpad nudge
  every 8 turns (was 3), read-only nudge after 6 turns (was 3).

- **Pi-style output truncation (2026-06-22)** — read_file now has hard caps at
  2000 lines / 50KB with pi-style continuation hints: `[Showing lines X-Y of Z.
  Use offset=N to continue.]`.  run_shell output is now TAIL-truncated (keep last
  2000 lines / 50KB) with full output preserved to a temp file (path shown in
  result).  Previously run_shell used HEAD truncation (dropped errors at end).
  Both now show actionable continuation hints instead of generic "truncated" msgs.

- **Windows command guidance (2026-06-22)** — System prompt now includes a
  WINDOWS COMMAND PATTERNS section teaching the model to use single quotes for
  python -c, prefer grep/head/tail via run_shell over read_file for filtering,
  and write temp scripts for multi-line Python.  shell_ops.py now detects
  likely-failing double-quote patterns in python -c on Windows and adds a
  warning hint.

- **hash_lines default changed (2026-06-22)** — Changed from True to False.
  The agent now only uses hash-anchored reads when it intends to edit, saving
  ~1 read per edit (no more forced re-read with anchors).  System prompt no
  longer requires hash_lines=True on every read.

- **Slimmer tool descriptions (2026-06-22)** — Simplified read_file, run_shell,
  and edit_file descriptions in schema.py.  Removed verbose "absolute max: 1000"
  notes, multi-file paths, and redundant implementation details.  edit_file
  description cut from 450→200 chars (saves ~60 tokens per API call).

- **Token efficiency guidance (2026-06-22)** — New TOKEN EFFICIENCY section in
  system prompt: use offset/limit, get_file_skeleton first, prefer find_symbol
  over search_files, batch independent calls, update scratchpad every 3 turns.

- **Tool-result-stubs injection fix (2026-06-22)** — `_inject_tool_result_stubs()` in
  context_inject.py had a silent failure for OpenAI tool-role format: when assistant
  tool_calls had missing tool results (after Dirac compaction truncated the conversation),
  stubs were counted but NEVER inserted into the messages list.  The comment said
  "skip rebuilding" for multiple tool_use_ids, leaving orphaned tool_calls that
  `_strip_orphaned_tool_messages` had to clean up (stripping the entire assistant
  message).  Fixed to: (a) scan ALL consecutive tool messages, not just the first;
  (b) properly insert stubs when next message is a text-only user; (c) initialize
  `needs_update` before format-specific blocks.

- **API clean-messages cache invalidation after compaction (2026-06-22)** —
  `_compact_if_needed()` rebuilds messages in-place (`clear()` + `extend()`), keeping
  the same Python list object ID.  The incremental cleaning cache in api.py
  (`_clean_messages_cache`) is keyed by `id(messages)`, so after compaction it served
  stale pre-compaction messages to the API.  Fixed by calling `clear_api_cache()`
  after `_compact_if_needed()` modifies the message list.

- **C/C++ AST-native tool support (2026-06-20)** — `get_file_skeleton`, `get_function`,
  (`.cpp`, `.cc`, `.cxx`, `.hpp`, `.hh`, `.hxx`). Uses tree-sitter-c and tree-sitter-cpp.
  Added `_get_declarator_name()` helper to traverse C/C++ declarator chains.
  Supports functions, structs, unions, enums, classes (C++), typedefs, namespaces (C++),
  templates (C++), and preprocessor macros. Call collection handles `call_expression` nodes.

- **AST tools Python `ast` fallback (2026-06-20)** — `get_function`, `get_file_skeleton`,
  `replace_symbol`, `get_symbol_range` now fall back to Python's built-in `ast` module
  when tree-sitter is not installed. Previously returned "Unsupported file type: .py".
  Added `_ast_fallback_definitions` and four fallback functions (+315 lines in ast_ops.py).

## Active Decisions

- **Dirac compaction HARD_LIMIT fix (2026-06-21)** — `_compact_if_needed()` used `HARD_LIMIT=1_000_000`,
  which meant models reporting 1M context windows (deepseek-v4-pro) never triggered the
  half/quarter conversation truncation. Every turn re-sent the full history, burning tokens.
  Added `COMPACTION_HARD_LIMIT=200_000` to `core/constants.py`.  Compaction now fires at
  200k tokens regardless of model-reported window, keeping API costs under control.
  Also discovered `core/cost_control.py` is entirely orphaned (never imported).

- **old_string fallback removed (2026-06-19)** \u2014 edit_file now requires hash-anchored mode exclusively.
  Removed `_apply_single_edit`, `_EditResult`, `old_string`/`new_string`/`count`/`paths` params.
  Schema updated: `from` and `from_hash` are now required. `generate_diff` uses line-range diffs.
- **edit_file flat args removed (2026-06-20)** — Deleted `_edit_file` wrapper. Both `edit_file` and `edit_lines`
  now route directly to `_edit_lines`, which accepts `edits` array (not flat `from`/`from_hash`).
  Tests and schema updated to match. `generate_diff` in safety.py still uses flat args (separate code path).
  Added `to`/`to_hash` defaults (fall back to `from`/`from_hash`) in `_edit_lines` for convenience.
  Fixed `test_restore_after_edit` in tests/test_file_ops_extended.py (missed flat-args conversion).
- **schema.py auto-generated (2026-06-20)** — Schema now compact JSON-lines, generated from @_register decorators.
- **Dirac-style half/quarter compaction (2026-06-19)** \u2014 replaced summary-based compaction with Dirac's pure-deletion approach.
- **Dirac-style anchor tracking (2026-06-18)** — AnchorStateManager with FNV-1a hashing, Myers diff, word anchor pool.
  Persistently tracks anchor words across edits so unchanged lines keep the same anchor.
  Bug fix: `_TrackedDocument` init param corrected from `available_pool` to `pool` in `reconcile()`.
  51 tests in `tests/test_anchor_manager.py` — all passing.
- **Storm-breaker (2026-06-16)** — after 3 consecutive identical failures, synthesize explanation instead of silent loop
- **Self-modifying architecture** — agent observes, diagnoses, and improves its own codebase via STATE.txt/CHANGELOG.md/HANDOFF.md
- **Context injection ZONE model** — ZONE 1 (immutable prefix), ZONE 2 (append-only log), ZONE 3 (volatile scratch)
- **Read-before-edit enforcement** — all .py edits require prior read_file this session; syntax validated via compile()

## Module Map

### Core Orchestration
- `core/constants.py` -- shared constants (MEMORY_FILENAME, HTTP_CONNECT_TIMEOUT, SKIP_DIRS, etc.).
  Zero internal project imports — safe to import from anywhere.
- `core/bootstrap.py` -- entry point, session init, workspace setup, startup warmup
- `core/llm.py` -- main agent loop: turn management, tool dispatch, API calls (825 lines)
- `core/codebase_map.py` -- AST-based symbol extraction, module grouping, import graph.
  Injected into startup context (~2K tokens). Incremental cache via update_file_in_map().
- `core/context_inject.py` -- per-turn context injection (handoff, state, tasks, scratchpad,
  git diff, orchestration, circuit breaker, compaction, edit risk, pattern rules) (1250 lines)
- `core/anchor_manager.py` -- Dirac-style persistent anchor state (FNV-1a hash, Myers diff,
  word anchor pool). Tracks anchors across edits so unchanged lines keep the same anchor.
  51 tests in `tests/test_anchor_manager.py`.
- `core/prompt.py` -- system prompt assembly, startup context
- `core/config.py` -- TOML config loading, provider settings (718 lines). Re-exports from constants.
- `core/tree_sitter_parser.py` -- multi-language (Python/JS/TS) symbol extraction via tree-sitter

## Architecture Notes

### Provider System
- Flash/Pro routing: `_compute_complexity()` uses last user message only (not accumulated history).
  Cache keyed by `hash(last_user_content)`.
- Fallback chain: primary → fallback providers on 429/5xx. DeepSeek defaults to Claude.
  Provider-specific params stripped. Only non-streaming.
- DeepSeek prompt cache key: `mini_agent-v1-{tool_count}` for KV-cache stickiness.

### Windows-Specific
- _communicate_windows() in shell_ops.py: read threads + threading.Timer watchdog with
  taskkill /F /T. CREATE_NO_WINDOW set; CREATE_NEW_PROCESS_GROUP removed (caused freeze).
- File reads bypass subprocess on Windows (`if False:` guard) — direct in-process reads.
- Startup warmup: cmd.exe /c rem runs during bootstrap to absorb antivirus scan delay.
- Bash path quoting: MSYS2 paths must be quoted when building bash wrapper commands.

### Agent Ops Split (2026-06-14)
- 3,880-line agent_ops.py monolith split: agent_spawn.py, agent_collect.py, agent_ops.py.
  Cross-references updated in agent_patterns.py, test_comprehensive.py, etc.

### Constants Consolidation (2026-06-14)
- MEMORY_FILENAME, HTTP_CONNECT_TIMEOUT, HTTP_READ_TIMEOUT moved to core/constants.py
  to break circular import (core.config ↔ memory.session). Re-exported for backward compat.

### Semantic Cache
- tools/semantic_cache.py: Tier 1 exact SHA-256 (~0ms), Tier 2 cosine similarity via
  CodeSearchNet embeddings. Adaptive thresholds with feedback loop. 15-25% cost reduction.

### Backend:response Handler Fix (2026-06-14)
- App.jsx removed `data.target === 'chat'` guard — Python backend never sets `target`
  field. All responses now shown as msg-status lines.

### Knowledge Confidence Scale
- _inject_confidence_web_search_nudge(): monitors 3 triggers (search misses, tool failures,
  read-only turns) with 4-turn cooldown. Constants: _CONFIDENCE_NO_RESULT_THRESHOLD=3,
  _CONFIDENCE_FAILURE_THRESHOLD=2, _CONFIDENCE_NUDGE_COOLDOWN_TURNS=4.

### Hash-Anchored Editing (2026-06-16)
- `tools/file_ops.py`: `_line_hash()`, `_compute_line_hashes()` -- replaced by word anchors from `AnchorStateManager`
- `read_file(hash_lines=True)`: returns `lineno Anchor│ content` format (word anchors) for constructing edit_lines calls
- `edit_lines(path, edits[{from, from_hash, to, to_hash, new_text}])`: hash-validated line-range edits
  All hashes validated before any edit applied; batch rejected on any mismatch with precise error.
  Edits applied bottom-up (reverse line order) to preserve pre-edit line numbers.
  Pattern from Akay/Howard Chen hashlines design. Reduces retries ~50% and output tokens 30-40%.
- Schema: `tools/schema.py` -- `hash_lines` param on `read_file`, full `edit_lines` tool definition
- AST tools: `tools/ast_ops.py` -- `get_file_skeleton`, `get_function`, `get_symbol_range`, `replace_symbol`
  now default to `include_anchors=True` (hash-anchored output matching read_file format). Schema and dispatch
  wrappers in `tools/file_ops.py` both updated. Same `lineno Anchor│ content` format for seamless piping to edit_lines.
- Tests: `tests/test_file_ops_extended.py::TestHashlines` (12 tests)

### Storm-Breaker (2026-06-16)
- `core/llm.py`: `_STORM_FAILURES` deque, `_check_storm_breaker()`, `_synthesize_storm_breaker_message()`
  After 3 consecutive identical failed tool calls (same name + error fingerprint), synthesizes
  an assistant-role message explaining the failure instead of silently continuing.
  Pattern from Howard Chen's cwcode: "don't crash, talk."
- Injected in `run_agent_turn()` after `_tool_execution_phase()`
- Tests: `tests/test_file_ops_extended.py::TestStormBreaker` (6 tests)

### Turn-Boundary Compaction Reverted (2026-06-22)
- Bug: `run_turn_boundary_compaction` called at EVERY turn boundary, which at
  HARD compaction level (80% context, ~turn 20-25 on DeepSeek) called
  `prune_stale_tool_results` that replaced tool results with compact placeholders
  in-place. This caused "tools never spawned in UI" and "AI doesn't see tool results."
- Fix: Reverted to bugfree behavior -- only `compact_tool_results_at_turn_end`
  (truncation, not pruning) at the turn boundary. The full compaction pipeline
  (`maybe_compact`, `prune_stale_tool_results`) now only runs through the
  existing `_compact_if_needed` call in `context_inject.py`.
- This matches the behavior in bugfree `E:\TEST_MINI_A\mini_agent`.
